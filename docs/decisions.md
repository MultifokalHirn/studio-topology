# Decisions log

Ambiguities in the spec resolved by picking the simpler reading (spec §0.2). Architectural deviations get an ADR in `docs/adr/`.

| # | Date | Topic | Decision |
|---|---|---|---|
| 1 | 2026-10-04 | Spec location | The spec moved to `docs/studio-planner-spec.md` per the repo layout in §2. |
| 2 | 2026-10-04 | Library versions | Scaffolded with current majors: React 19, Vite 8, TypeScript 6, Tailwind 4 (CSS-first config, no `tailwind.config.js`), Zod 4, ESLint 10 flat config, Vitest 5. All satisfy the spec's "React 18+". |
| 3 | 2026-10-04 | Domain/engine purity | Enforced by ESLint `no-restricted-imports`/`no-restricted-globals` on `src/domain/**` and `src/engine/**`, not only by convention. |
| 4 | 2026-10-04 | Types vs schemas | Types are inferred from the Zod schemas instead of hand-written next to them. See [ADR 0001](adr/0001-types-inferred-from-zod.md). |
| 5 | 2026-10-04 | Stable key order | Saved JSON sorts object keys alphabetically at every level; arrays keep their order. Two-space indent and a trailing newline. Simplest ordering that is deterministic regardless of how an object was built. |
| 6 | 2026-10-04 | Unknown fields on load | Zod strips unknown keys, which would lose data on the next save. The loader treats unknown keys as a schema issue (listing their paths) and offers read-only opening instead of dropping them. |
| 7 | 2026-10-04 | Read-only "load anyway" | Read-only mode loads the raw, unvalidated document. Edits and saves are refused. Views must tolerate missing fields when rendering it. |
| 8 | 2026-10-04 | Bottom face orientation | §3.2 does not define it. The bottom face is viewed from below with the back edge at the top of the image, so the face-local x runs right to left in body coordinates. Top: viewed from above, back edge at the top of the image. Left/right: viewed from that side, top up. |
| 9 | 2026-10-04 | Settings shape | §4.1 lists the settings topics without a type. Concrete shape in `schemas.ts` (`Settings`). Defaults in `defaults.ts`. |
| 10 | 2026-10-04 | Template shape | `Template` = `{ id, name, group, target: 'gear'\|'stand'\|'connectors', params?, gear?: Partial<GearModel>, stand?: Partial<StandModel>, connectors? }`. `params` covers "N keys", "N channels", "N U" and similar. |
| 11 | 2026-10-04 | Tilt axis | A surface tilts about the x-axis through its front edge, and positive tilt raises the back edge (§7.2). |
| 12 | 2026-10-04 | Atomic writes | The File System Access API's writable stream already writes to a swap file and replaces the target on `close()`. On error we `abort()`. No extra temp handle is needed. |
| 13 | 2026-10-04 | `updatedAt` | Set at save time, not on every edit, so undo/redo restore states exactly. |
| 14 | 2026-10-04 | Undo depth | History keeps 500 entries (spec minimum: 200). |
| 15 | 2026-10-04 | Schema extensions for the gear reference | These additions let every device in the gear reference be represented without inventing values. Jack types: `jack-6.35` / `jack-3.5` (pole count not documented), `wireless` (BLE MIDI), `mains-plug` and `captive-cable` (wall-warts), `unknown`. Barrel `odMm`/`idMm`/`polarity` are nullable. Channel role `stereo` covers one stereo jack. `Connector.insert` = tip/ring send/return. USB audio channel counts are nullable. Clock formats `pulse-step` (KeyStep) and `po-sync` (Pocket Operator). `InternalPath.group` + `UnitConfig.pathPresets` give per-channel patchbay modes. `PowerSpec.busRails` covers Eurorack cases. `Template.connectorGroups`/`generator`. `schemaVersion` stays 1 because no file format has been released yet. |
| 16 | 2026-10-04 | Seed authoring | Seed models are written by hand in TypeScript (`scripts/seed/*.ts`) with small helpers. `npm run seed:build` compiles them to `/seed/**/*.json`, and CI checks for drift (`seed:check`). This satisfies "converted by hand, not by a parser" while avoiding ~650 hand-typed connector objects. |
| 17 | 2026-10-04 | Provenance keys | Keys may use `*` for any index (`connectors.*.pos`). Lookups inherit from parent paths (`connectors.3.usb.audio` covers `.inChannels`). Every `null` in dimensions/power/connectors must resolve to a provenance entry (`ensureUnknownProvenance`, checked by `seed:validate` and the editor). |
| 18 | 2026-10-04 | Multichannel port refs | Internal-path `channelMap` entries may address one channel of a multichannel port as `connectorId:n` (ADAT). |
| 19 | 2026-10-04 | Power wiring | Included supplies are gear models (category `power`) with a `captive-cable` DC output carrying a `psu` rating. Setups wire them to units as ordinary `power.dc` connections. `UnitConfig.powerAssignments` stays available for supplies not modelled as units. Mains wiring is not in the sample because the reference lists no power strips. |
| 20 | 2026-10-04 | Insert and patchbay jacks | Insert jacks and patchbay points are `direction: 'bidir'` analog connectors. Inserts carry `insert.tip/ring`. Rules (M6) must treat them specially. |
| 21 | 2026-10-04 | Derived draw | Where the reference gives only watts, `drawMa = W / V`, flagged `estimated` with the formula in the note. |
| 22 | 2026-10-04 | Sample project | Built from the gear reference. "Current" is a demo arrangement (the real one is unknown). "Planned (standing)" uses the spec §8.1 tier assignment. The iPad is the 11" model (size unconfirmed). The reference lists no monitors or headphones, so traces end at the SSL 12 outputs. The sample loads on first launch when nothing is autosaved, and the top-bar ✦ button reloads it. |
| 23 | 2026-10-04 | Gear editor forms | Common fields get dedicated forms whose enum options come from the Zod schemas. Nested structures (connector MIDI/USB/clock/PSU/alternates, MIDI spec, clock spec, path channel maps) use a schema-validated JSON editor. This keeps every schema field editable without building a generic form generator. |
| 24 | 2026-10-04 | Provenance on edit | Instead of a prompt on every edit, the editor has a per-session "New values are: user / measured / …" selector. Clearing a value records `unknown`, never `user`. |
| 25 | 2026-10-04 | Mark verified | The bulk action turns `estimated` entries into `user` with a dated note. `unknown` (null) values stay unknown until a value is entered. |
| 26 | 2026-10-04 | Editor drafts | Drafts live until Save or Cancel (one undo step on Save). Draft autosave across reloads is deferred. |
| 27 | 2026-10-04 | Categories | Free text with suggestions; nothing branches on it. See [ADR 0002](adr/0002-free-text-categories.md). |
| 28 | 2026-10-04 | Mains | New jack `mains-socket` and plug `Mains-plug` (country-neutral; set the region in notes). Strips and PDUs are gear with `power.ac` outlets (each with a `psu` rating) plus `power.distribution` = shared voltage and total current, switched, surge protection. IEC devices connect via the `IEC C13 → mains plug` cable; wall adapters plug in directly (captive). The sample adds two 8-way strips and a 1U PDU tagged `placeholder`, because the gear reference lists none. |
| 29 | 2026-10-04 | Racks and rack cases | "11\" rack gear" was read as 19" (likely a typo). 10" half-rack is supported too. Rack gear declares `dimensions.rack.standard` (default 19"); bays declare `rack.standard`, inner width (450 / 222.25 mm), depth and rear rails. `StandType 'rack-case'` and a parametric "Rack case" template exist. `rackFit` reports overlap, out-of-range, too deep, 19" in 10" (error) and 10" in 19" (needs adapter). Fractional heights round up (11.2U → 12U). Rack gear with an unknown height counts as 1U with a warning. Desktop gear goes on a "Rack shelf" (stacked placement). |
| 30 | 2026-10-04 | Stands on stands | `StandState.onSurface` puts a stand (e.g. a rack case) on another stand's surface. Geometry adds the parent surface height (`standBase`). Parent tilt is not yet applied to the child (revisit in M4). Cycles are flagged by the integrity check. |
| 31 | 2026-10-04 | Rack configuration before M4 | Until the layout canvas exists, the stand inspector fills rack bays U by U for the active setup (add at the first free or a chosen U, remove, see problems). |
| 32 | 2026-10-04 | Cables | Cable types get `manufacturer`, default `color` and `tags`. Owned cables (`CableUnit`) get `color`, `endLabels` and `notes`. A connection can reference the owned cable used (`cable.unitId`). Colour precedence: connection → owned cable → cable type → signal palette. Auto-labels number unlabelled cables per signal family (A = audio, D = digital, M = MIDI, U = USB/network, C = CV/clock, P = power, X = control). Stereo bundles share a number with an L/R suffix, and numbering continues after existing labels. |
| 33 | 2026-10-04 | Monitoring templates | "Monitor speaker (single)" is added once per speaker (the dialog can add N units, e.g. an L/R pair). The spec's "Monitor speakers (pair)" template is kept for people who model a pair as one item. Also added: subwoofer, monitor controller (N speaker sets, N headphone outs), headphone amp, headphones, a blank custom template, and "Save as template" for your own reuse. |
| 34 | 2026-10-04 | Asset storage | Images are embedded as data URIs until M10. See [ADR 0003](adr/0003-embedded-assets-first.md). |
| 35 | 2026-10-04 | Image import | PNG/JPEG/WebP/SVG are decoded through `createImageBitmap` with a 100 MP limit checked before pixels are allocated. Images are re-encoded to WebP 0.85 (PNG where the browser has no WebP encoder) at ≤ 2048 px; metadata is dropped by re-encoding. SVG is rasterised too, for one uniform path. |
| 36 | 2026-10-04 | Image ↔ face mapping | A face image's top-left is the face's top-left. Image size in mm = pixels ÷ `pxPerMm`. After import, `pxPerMm = width px ÷ face width mm` (assumes the photo spans the face) with `rectified: false`. Rectification sets the exact value. Pixel processing (homography, warp, crop, rotation, flood fill) is pure code in `domain/` and tested headless. |
| 37 | 2026-10-04 | Placed vs. unplaced | A connector is "placed" when its `connectors.N.pos` provenance is anything but `unknown`, or, with no provenance at all, when it is not at the (0,0) placeholder. Placing stamps the session provenance kind (user/measured…). |
| 38 | 2026-10-04 | Mirror helper | "Move to opposite face" keeps the physical spot (x → width − x on the opposite face, §3.2). "Mirror x" re-reads a position measured from the wrong side on the same face. "Move all placed to back/front" applies it to a whole panel. |
| 39 | 2026-10-04 | Port glyphs | One glyph per jack type, drawn at approximate real cut-out size (e.g. ¼" jack ≈ 12 mm, XLR ≈ 22 mm, DIN ≈ 19 mm, IEC ≈ 26 mm). These sizes are drawing aids, not data. |
| 40 | 2026-10-04 | Editing images in the editor | Images added during a gear-editor session are staged and only written to the project on Save. Unreferenced assets are pruned then, so Cancel never leaves orphans. |
| 41 | 2026-10-04 | Face tab | Edits the project directly: a drag is one undo step (coalesced and sealed on release). Arrow keys nudge 1 mm (Shift = 10 mm). Snap uses the settings grid (5 mm); Alt disables it and Shift snaps to 1 mm. |
| 42 | 2026-10-04 | Eye position for occlusion | The eye sits above the setup datum (x = 0, y = 0, the listening position, §3.2) at the body profile's eye height for the setup's posture. The lower unit's controls plane is treated as horizontal at its mid-depth control height. Tilt changes the projected depth only slightly at the angles used; revisit if needed. |
| 43 | 2026-10-04 | Occlusion scope | Only controls the player uses count: lower units on the floor, in racks, or marked `set-and-forget` are not checked, and floor items never occlude. Units must overlap in x. "Hand room" (PLC-005 clearance) is the gap between the lower unit's top and the upper unit's underside including the holder thickness, compared with the hand clearance (90 mm). It is only checked when the units overlap in plan. |
| 44 | 2026-10-04 | Row plane | A row's control plane is the highest control plane among its units; pitch is upper row plane − lower row plane. "Overhang" = any upper unit overlaps any lower unit in plan. |
| 45 | 2026-10-04 | Width budget | PLC-002's width-sum check applies to single-row tiers only. Desks and shelves are 2-D and use per-unit bounds. Tier units may overhang the holders in depth; PLC-004 covers that. |
| 46 | 2026-10-04 | Unknown sizes on canvas | Placeholders per form factor (desktop 250 × 200 × 60 mm, rack 1U × 250 mm, …). Keyboards with a known key count get their width from the key pitch (KeyStep 32 slim → 500 mm). Estimated units draw dashed and raise DATA-001. |
| 47 | 2026-10-04 | Tier adjustments | Heights, tilts and depth offsets entered or dragged snap to the stand's adjustment step and clamp to its range (the Jaspers has 5 mm steps per Appendix D). The sample's standing plan uses 725 / 920 / 1125 mm (planes ≈ 800 / 1000 / 1190 mm). |
| 48 | 2026-10-04 | Measure helper | Measured tier offsets are stored as the setup's surface state (upper tier y/z relative to the lower tier), not in the stand model, because the A-frame offsets depend on how the stand is set up. Measured values clear the "unknown offsets" banner. |
| 49 | 2026-10-04 | Rack positions | In a bay of N U, U1 is the top. A unit at `uStart` spans downward; its bottom sits (N − uStart + 1 − height U) × 44.45 mm above the bay floor. Rack gear is centred on the bay (ears overhang the 450 mm opening). |
| 50 | 2026-10-04 | Layout interaction | Front view: horizontal drag moves along the surface; a vertical drag of more than 60 mm hops to the nearest surface under the pointer; rack gear moves by whole U. Plan: drags move in surface coordinates (stand rotation undone). Side: drags change depth. Drops from the Inventory land on the surface under the pointer, else on the floor. Delete removes from the setup (the unit stays in the inventory), R / Shift+R rotate, arrows nudge 1 mm (Shift 10 mm). Drags coalesce into one undo step. |
